# Cortex: a small, auditable, human-owned graph memory for AI agents

*Design paper for engine v2.5.3. Code references point to `template-vault/_brain/scripts/brain_core.py` (abbreviated `bc:<line>`). The measurements in §10 come from the demo vault in `examples/` and from the engine's test suite. No figures come from private deployments.*

## Abstract

Cortex is a long-term memory for language-model agents, built from plain Markdown files in a git repository. Notes sit in three layers (domains, concepts, details) with hard word limits, under a generated map that every session loads. Agents read through a budgeted funnel: `recall` returns one-line signatures ranked by a field-boosted BM25 score scaled by a damped usage weight, and `read` hands over a few bodies before the engine answers with exit code 2. Usage events feed an exponentially decayed weight, a power-law ACT-R activation that selects a "Hot" list for the map, and pairwise co-activation that proposes new links in a weekly "sleep cycle". An agent can add its own knowledge only as a *provisional* fact. The engine validates the fact before writing it, ranks it low, and confirms it only after use in three separate sessions. A curator agent tidies the graph, and only the human marks knowledge consolidated. The engine is one ~3,000-line Python file that uses only the standard library. A pre-commit hook rejects secrets and schema errors and regenerates every derived view. This paper describes what the code computes, why, and where it falls short.

## 1. Motivation

An agent that forgets everything between conversations makes people repeat themselves. One that remembers everything has a different problem: its memory grows without bound, cannot be audited, fills the context window, and quietly accumulates wrong or sensitive facts. Cortex aims for a memory with four properties:

1. **Small at the point of use.** A lookup should cost a few hundred tokens, not a document dump. The cost should be bounded by construction, not by the agent's restraint.
2. **Auditable.** Every fact is a readable file with a source and a date. Every change is a commit someone can read, revert or blame.
3. **Human-owned.** Agents may propose knowledge. Only a human promotes it to trusted status, and no agent can write secrets or personal data past the gate.
4. **Honest about time.** A fact true last month may be false today. The memory should say which facts describe the present, which are records of the past, and which are known to be wrong.

Vector stores satisfy (1) only loosely and (2)–(4) poorly. Raw note folders satisfy (2) and (3) but not (1). Cortex combines a strict note schema with a retrieval engine that enforces budgets, and puts git and a validating hook between every writer and the history.

## 2. Architecture

A **vault** is a directory and a git repository (`template-vault/`):

```
AGENTS.md  CLAUDE.md  MAP.md              L0: conventions + generated map
<Domain>/<Domain>.md                      L1
<Domain>/<Concept>.md                     L2
<Domain>/<Concept>/<Detail>.md            L3
_inbox/ _sources/ _log/ _archive/         cold ring (not searched)
_brain/scripts/brain.py, brain_core.py    the engine (+ panel.html, lexicons, tests)
_brain/config.json, glossary.json         per-vault settings
_brain/generated/ Panel.* state/          derived views and runtime state
.githooks/pre-commit                      lint + regenerate
```

The engine is a CLI (`bc:2840–2961`) with read commands (`session`, `recall`, `read`, `credit`), an agent-write command (`learn`), curator commands (`new`, `link`, `unlink`, `move`, `promote`, `demote`, `rename`, `status`, `consolidate`, `external`), and maintenance commands (`lint`, `build`, `precommit`, `doctor`). Exit codes carry meaning: 0 ok, 1 usage or validation error, 2 budget or limit spent (`bc:7`). An agent therefore learns "stop and answer" from the exit status, without parsing any text.

`brain.py` is a 15-line shim that imports `brain_core`. A script run directly is recompiled on every call, while an imported module's bytecode is cached, so the shim keeps the per-call cost of the large file low. The vault loader walks the tree with `os.scandir` and pickles the parsed vault to `state/snapshot.pickle`, keyed by every file's mtime and size (`bc:591–660`). An unchanged vault loads with one unpickle, and a changed one re-parses only the files that changed. The BM25 index (`bc:1266–1311`) and the usage accumulators (`bc:757–801`) are cached the same way. Cached state is keyed by engine version, engine file mtime and size, and Python version (`bc:470–476`), so an upgrade invalidates it automatically.

All derived views are regenerated by `build` (`bc:2765–2785`): `MAP.md`, `_brain/generated/index.tsv` (one row per node, the only file agents may grep), `graph.json`, `orbit.svg`, `hot.md`, `Panel.md` and a self-contained `Panel.html`, which inlines the vault data into `panel.html` and draws a 2D orbit view and a 3D sphere view. The hook runs `precommit` (lint, then build on a single vault load, `bc:2752–2762`) and stages the regenerated files.

## 3. Layers and limits

Each node has YAML frontmatter (`id, layer, type, summary, up, aliases, status, source, external, created, updated, reviewed`, `bc:64–65`). Its place in the hierarchy is both a property (`up`) and a path, and lint warns when the two disagree (`bc:1081–1102`).

| Layer | Types (`bc:34`) | Word limit (`bc:42`) | Role |
|---|---|---|---|
| L0 | — | — | `AGENTS.md` (hand-written conventions) and `MAP.md` (generated domains plus Hot list) |
| L1 | `domain`, `tools` | 250 | a domain's synthesis and its branches |
| L2 | `concept`, `tool` | 300 | one standing fact or rule, and why it matters |
| L3 | `fact`, `procedure`, `example`, `error`, `decision` | 300 | one lesson or episode with its evidence |
| cold | — | — | inbox, sources, logs, archive: read only with `--cold "<reason>"` |

Other hard limits: a summary of at most 140 characters with no links (`bc:43`, `bc:972–978`), a title of at most 80 characters with no characters that break filenames or links (`bc:44`, `bc:61`), at most 7 synapses per node (`bc:40`), and at most 3 folder levels (`bc:46`). Lint warns above 12 concepts under one L1 (`bc:45`) and truncates a body above 2,000 characters when it is handed over (`bc:47`, `bc:1693`). Word counts cover only the node's own text: lists of children and links are an index, not content (`bc:456–457`). Dated episodes (`type: example`, `truth: historical`) are exempt from the word limit, because evidence is not atomized (`bc:460–464`).

The limits serve the budget. A signature is a title and a summary of at most 140 characters, so one recall line costs a bounded number of tokens. Because a body is at most 300 words, a `read` is bounded too. The map lists domains, not everything, and stops after 32 lines (`bc:2563`).

## 4. The budgeted retrieval funnel

### 4.1 Scoring

`score` (`bc:1415–1468`) is BM25 (k1 = 1.2, b = 0.75, `bc:1236`) over five fields with boosts title 5, aliases 4, summary 3, tags 2, body 1 (`bc:1235`). The body field excludes sections that only list other nodes (`Branches`, `Details`, `Connections`), which would otherwise make every parent match its children (`bc:1254–1263`). Terms are case-folded, accent-stripped, stopword-filtered, and stemmed with a light English suffix stripper truncated to 8 characters (`bc:142–157`). On top of BM25:

- **Phrase bonus.** ×1.5 when the whole normalized query occurs in the title (`bc:1445–1446`).
- **Unknown words.** A query term absent from the vault is replaced by its `synonyms_en.tsv` group at weight 0.5 (`bc:1245`). Failing that, it becomes the vault term with the highest trigram Jaccard similarity, if that is at least 0.5 (`bc:1242`, `bc:1394–1412`). Only unknown words are expanded. A comment records that expanding known words cost top-1 accuracy on the author's benchmark (`bc:1243–1244`).
- **Family lift.** An L2 concept inherits 0.5 × its best L3 child's raw score (`bc:1239`, `bc:1449–1457`), so a concept whose facts were moved into details still surfaces.
- **Detail first.** A detail that matches at least as well on its own as its concept is placed just above it, because the detail holds the fact (`bc:1462–1466`).
- **Weight and status.** The final score is `s · (1 + 0.5·√w) · status_factor · truth_factor` (truth factor since v2.8.0, see §11) (`bc:1459`), where `w ∈ [0,1]` is the usage weight of §5 and the status factor is provisional 0.6, seed 0.8, consolidated 1.0, obsolete 0 (`bc:37`). The square root and the 0.5 damp usage so that popularity breaks ties without overriding relevance. A provisional node's weight is forced to 0: use confirms it, but never ranks it (`bc:1458`).

Spanish queries are translated before scoring (`bc:1352–1372`): longest-match lookup in the engine's `lexicon_es.tsv` and the vault's `glossary.json` (the vault wins), matched by a light Spanish stem. Spanish function words are dropped, and "6 de octubre" becomes `10-06`. Storage stays English, and lint warns on Spanish titles or summaries (`bc:1073–1076`).

### 4.2 Output under a budget

`traverse` (`bc:1503–1536`) prints signatures for the top results and, for the first `expand` of them, context lines: the parent chain (`↑`) and typed neighbours (`↳`), ordered by synapse type priority (`depends_on`, `contradicts` and `supersedes` first, `related` last, `bc:39`), then co-activation, then weight. Context lines carry titles only. Output goes through a line and character budget, and context never displaces the first 5 primary answers (`bc:1246`, `bc:1518–1520`). The modes (`bc:78–82`):

| Mode | top | expand | bodies/query | bodies/session | queries/session | output cap |
|---|---|---|---|---|---|---|
| quick | 5 | 0 | 1 | 8 | 8 | 8 lines, 900 chars |
| normal | 8 | 3 | 5 | 20 | 10 | 20 lines, 900 chars |
| deep | 15 | 6 | 12 | 40 | 15 | 45 lines, 4,000 chars |

### 4.3 The answer gate

Often a single node clearly answers, and a second call to read it is wasted. `recall` prints that node's body directly under `# answer:` when four conditions hold (`bc:1600–1614`, `coverage` at `bc:1471–1481`):

- the node is an L2 or L3 seed or consolidated node, not yet read in this session;
- its title, aliases and summary cover at least 70% of the query's idf weight (`GATE_COVERAGE`, `bc:57`);
- at least two query words match there;
- the runner-up's coverage is strictly lower.

The code comment records why coverage was chosen over a score margin: on the author's benchmark, a score margin of 1.7× or more was still wrong in 8 of 14 cases, while the coverage gate fired on 24 of 240 questions with one error, which the runner-up condition removed (`bc:53–56`).

### 4.4 Reading, excerpts and sessions

`read` (`bc:1707–1753`) charges one body against both the query budget and the session budget. It refuses a second read of the same node (exit 2, "it is already in your context"). Cold-ring notes need `--cold "<reason>"`. A body over 600 characters (`bc:51`) is cut to an **excerpt** (`bc:1621–1678`): the body is split into sentences, list items, table rows and code blocks, each unit is scored by the idf of query terms it contains, and units scoring at least 0.35 of the best unit are kept (`bc:52`). The lead sentence, each kept unit's heading and a table's header rows are kept too. If the excerpt would keep more than 70% of the body, the whole body is returned. `read --full` hands over the rest once, at no budget cost.

Sessions are automatic (`bc:905–924`). Calls share a session until 600 seconds of idle time (`bc:60`), until the query limit is reached, or until a call asks for a deeper mode. When an automatic session closes having read bodies but credited none, the engine credits the last body read (`bc:944–954`): the funnel stopped there, so that node most likely answered.

## 5. Activation and weighting

Every recall, read, credit and validation appends an event to `state/usage.jsonl` (`bc:725–741`). Each event type has a weight (`bc:66`):

| event | written by | weight |
|---|---|---|
| `activated` | listed by `recall` | 0.2 |
| `read` | `read`, or a gated body | 1.0 |
| `used` | `credit` (and auto-credit) | 3.0 |
| `validated` | the human's `status … consolidated` | 5.0 |

The engine derives three quantities from this log.

**Weight (ranking, panel, consolidation).** For node *i*, `W_i = Σ_e w_e · 0.5^(age_e / h) + 0.5 · indegree_i`, where `h` is `half_life_days` (default 30) and `indegree` counts synapses pointing at the node. The weight is normalized by the vault maximum to [0, 1] (`bc:803–808`). The decayed sum is maintained incrementally: each event adds `w · 2^((t − t0)/h)`, and the running total is multiplied by `0.5^((now − t0)/h)` when read (`bc:757–801`). That equals the decayed sum exactly, without re-reading the log on every call. `weights_from_log` recomputes it from scratch as a reference (`bc:815–825`).

**Activation (the Hot list).** Hot memory uses the ACT-R base-level learning equation with power-law decay, not exponential decay: `B_i = ln Σ_e w_e · max(age_hours, 1)^(−0.5)` over reads, uses and validations (`activated` events excluded: being listed is not being needed) (`bc:841–850`, `HOT_DECAY` at `bc:70`). `hot_nodes` takes the L2/L3 nodes with `B ≥ −2.6`, excluding obsolete and provisional nodes, and keeps at most 8 (`bc:71–72`, `bc:2478–2483`). The threshold −2.6 is about one read a week ago (ln 168^−0.5 ≈ −2.56, `bc:69`). `build` writes the list into `MAP.md` under *Hot*, and `credit` refreshes `generated/hot.md` (`bc:2543–2551`). Since `MAP.md` is loaded at the start of every session, an agent can answer from a hot summary with no tool call and then credit it. `doctor` reports how often that happened (`bc:2499–2528`).

Two decay laws are used on purpose. Exponential decay with a 30-day half-life gives a smooth, slowly moving weight suited to ranking and pruning. The power law drops sharply over the first hours and then flattens, which favours what was needed recently and repeatedly, the behaviour ACT-R models for human recall.

**Co-activation (Hebbian links).** All nodes credited in one `credit` call share a group id. Each unordered pair in a group accumulates the group's decay factor (`bc:790–796`, `bc:810–813`). Pairs used together accumulate strength, and the strength decays with the same half-life.

## 6. Consolidation: the sleep cycle

`consolidate` (`bc:2185–2252`, `bc:2271–2319`) computes proposals and writes them to `_brain/proposals.md` as checkboxes. It never applies judgment-dependent changes itself:

- **Hebbian synapse**: a pair with co-activation ≥ 2.9 (`bc:41`, about three recent joint uses) and no existing parent or synapse link. The curator must write the reason. A synapse without a reason fails lint (`bc:1111–1112`).
- **Prune**: a synapse whose ends have co-activation < 0.05 and weights < 0.1, both older than 90 days.
- **Archive**: a seed with weight < 0.05, older than 60 days and with no children; a provisional node never used in 30 days.
- **Atomize** a node over its word limit. **Subdomain** for an L1 with more than 12 concepts.
- **Promote**: an L2 in the top decile by weight (and above 0.5) with at least 5 details, or an L3 in the top decile used at least 5 times. **Demote**: an L2 with no details, weight < 0.1 and older than 60 days.
- **Merge**: same-layer nodes whose title and summary stems have Jaccard ≥ 0.75.
- **Synthesis**: an L1 whose descendants were updated after it was.
- **Learnings**: pending provisional nodes, contradictions to decide, confirmed nodes to sample. **Validate**: seeds older than 30 days with no human review. **Inbox**: captures to atomize.

Only archiving and pruning are mechanical, and `consolidate --apply` performs them for the boxes the curator ticked (`bc:2273–2307`). The curator handles the rest through the skills in `skills/consolidate`, `skills/atomize` and `skills/link`. The skills rewrite L1 syntheses bottom-up from branch summaries, so the top of the tree is always a summary of what lies under it.

## 7. Provisional learning and confirmation by use

Agents learn things while working: a port that changed, a fix that worked, a preference the user stated. Letting them edit the memory freely leads to drift and duplication, and can leak secrets. Forbidding it loses the knowledge. Cortex gives agents one narrow write path, `learn` (`bc:1820–1875`), which validates the whole learning before it writes anything:

- type ∈ L3 types; parent is an existing L2; title valid and unique; summary ≤ 140 characters with no links;
- non-empty `--content` and `--evidence`, no `[[links]]`, at most 300 words together;
- title and summary not Spanish (`looks_spanish`, `bc:160–170`);
- no secret or email address (`sensitive`, `bc:1804–1817`, the same patterns as lint);
- no existing node whose title and summary stems overlap ≥ 0.6 (Jaccard), unless the learning names that node with `--contradicts`;
- fewer than 25 provisional nodes pending (`max_provisional`); otherwise exit 2 and the learning goes to `_inbox/`.

The new node gets `status: provisional`, `learned_by`, `truth` (default `current`), and a `contradicts` synapse if one was given. Its parent's `Details` list gains a line. Agents never edit, move or link existing nodes. A node an agent believes is wrong is answered with a new learning that contradicts it, and the curator decides between them.

A provisional node ranks at 0.6× and ignores its own weight, so it cannot push itself up. On every `credit`, `confirm_provisional` (`bc:1783–1801`) promotes it to `seed` once three conditions hold:

1. it has been credited in at least 3 distinct sessions (`confirm_sessions`);
2. it is at least 2 days old (`confirm_min_days`);
3. it has no `contradicts` synapse in either direction.

The node then records `confirmed: <date>`, and `consolidate` lists it for the curator to spot-check. The design treats repeated usefulness across separate sessions and days as evidence. One enthusiastic session cannot confirm its own guess, and a disputed fact waits for a decision.

## 8. Truth model

`status` says how much the system trusts a node. `truth` says what kind of claim it is:

- `current`: describes the present. Anything measurable must be verified against the live system before it is stated, because the live system always wins.
- `historical`: a dated record. It is never evidence of present state.
- `superseded`: known to be wrong now, and kept only for its lesson.

The two axes are independent. A consolidated node can be historical, and a provisional learning can be current. The engine stores `truth`, exempts historical episodes from the word limit (`bc:460–464`), and accepts `--truth current|historical` on `learn`. The rest of the truth model is a convention in `AGENTS.md` that the agent follows when answering. Typed synapses complete it: `contradicts` and `supersedes` sort first among context lines (`bc:39`), so a recall shows a node's challenger next to it.

## 9. Multi-agent topology and safety

**One vault per agent, one curator, one human.** Each agent gets its own vault, holding its role, environment, procedures and lessons, so each memory stays small and focused. Vaults that know each other are *siblings* in `config.json`. A node can point into a sibling with an `external` reference (an `obsidian://` URI, `bc:2323–2335`) instead of copying it. `recall --all` searches siblings with half the line and character budget (`bc:1587–1599`). `rename` rewrites references in siblings (`bc:2103–2123`). `doctor` requires every sibling to run the same engine version (`bc:2816–2829`). The roles:

| Actor | May |
|---|---|
| reader agent | `recall`, `read`, `credit`, `learn`, write to `_inbox/` |
| curator agent | all of the above, plus `new`, `link`, `move`, `promote`, `demote`, `rename`, `consolidate`, commits |
| human owner | everything, and alone `status … consolidated` |

The engine does not enforce these roles: any process with file access can run any command. They are enforced by the instructions each agent receives (`installers/wire_agent.py` writes a reader or curator block), by `learn` being the only write path documented for readers, and by git history, which shows who changed what.

**Safety gates in code.**
- Secret patterns (private keys, AWS keys, `sk-`/`ghp_`/`xox` tokens, connection strings with passwords, `password:`/`contraseña:` followed by a value containing a digit or symbol, and generic `token=`/`api_key=` values of 16 or more mixed characters) are lint **errors** that block the commit (`bc:93–103`, `bc:1144–1159`). The same check refuses a `learn` (`bc:1804–1817`, `bc:1844–1846`).
- Email addresses with a real top-level domain are warnings in lint and refusals in `learn`. Hosts on `.local`, IP addresses and version strings such as `uv@0.13.0` do not match (`bc:104–105`). Deliberate addresses go in `allowed_addresses` with a reason.
- Writes take an inter-process lock file, broken after 30 seconds (`bc:241–267`), and use atomic rename (`bc:204–209`).
- Generated files are never edited by hand. The hook regenerates them on every commit.

## 10. Measurements on the demo vault

The demo (`examples/fern-cortex`, sibling `examples/kitchen-cortex`) is a fictional gardening agent, Fern, working for a fictional gardener, Sam. It has 16 nodes (3 L1, 7 L2, 6 L3) and its sibling has 4. It was created with `scripts/new_vault.py --from`, on Linux with Python 3.14.4, on 2026-10-30. The runs below used a fresh copy.

- **Answer gate.** `recall "when should the beds be watered"` listed 3 signatures and printed the body of *Water before 9 am* under `# answer:` ("its title and summary cover 100% of the question"), so no `read` was needed. Total output: 1,098 characters. Recalls without the gate printed 610–970 characters.
- **Spanish.** `recall "cuando hay que regar el huerto"` printed `# searched as: water watering garden plot` and listed *Water before 9 am* third, after two L1 domains.
- **Typos.** `recall "planting calender for tomatos"` put *Planting dates count from the last frost* first.
- **Budgets.** In a quick-mode session, the first `read` succeeded and the second returned exit 2 ("query budget exhausted (1 bodies)"). The ninth recall returned exit 2 ("limit of 8 queries"). In normal mode, reading the same node twice returned exit 2.
- **Learn refusals.** All three exited with 1: a 141-character summary ("summary of 141 characters (max 140)"), an email address in the content ("possible email address"), and a Spanish summary ("Spanish words: el, en").
- **Confirmation and Hebbian proposal.** The provisional *Copper tape kept slugs off bed B* was back-dated to 3 days old to satisfy the 2-day minimum. Three sessions each credited it together with *The drip timer runs 20 minutes at 7 am*. The third credit printed `confirmed "Copper tape kept slugs off bed B": provisional → seed`. `consolidate` then proposed one Hebbian synapse between the two nodes (co-activation 3.0) and one "sample" item for the confirmed learning. After `build`, both nodes headed the Hot list in `MAP.md`.
- **Hook.** Appending `password: hunter2!x` to a note and committing printed `possible secret (password)` and `commit blocked`, with exit 1.
- **Latency.** A warm `recall` took 0.04 s wall-clock (5 of 5 runs). After the caches were deleted it took 0.05 s. The test suite's synthetic 1,000-node vault measured: build without cache 0.19 s, precommit with cache 0.11 s, recall 0.05 s, recall output 908 characters (`tests/test_brain.py:424`).
- **Panel.** `Panel.html` for the 16-node vault was 108,013 bytes, self-contained.

These runs exercise the mechanisms. They are not a retrieval benchmark. The comments in the code cite the author's private benchmarks (for example 240 questions over 4 vaults for the gate), and those data are not part of this repository.

## 11. Limitations

- **Lexical retrieval only.** BM25 with synonyms and typo repair finds what is *worded* similarly. Paraphrases with no shared word, synonym group or glossary entry miss, and recall then falls back to listing the L1 domains.
- **The light stemmer is uneven.** Stripping `-y` as a suffix maps "deploy" to `depl` but "deploys" to `deploy`, and "tuesday" to `tuesd` but "tuesdays" to `tuesday` (`bc:142–153`). Singular and plural forms of such words do not match. Aliases or a synonyms line work around it. A fix would change ranking, so it belongs in a versioned engine release, not in this export.
- **Truth affects rank only when tagged or linked.** Since v2.8.0 a node tagged `truth: superseded`, or the target of a `supersedes` synapse that is not tagged `historical`, scores ×0.4 and is never lifted above its concept, so on the demo `recall "what is the soil pH"` answers with the current reading, not *The 2025 soil test read pH 5.8*. A historical record keeps its weight even when replaced, because questions about the past need it. A stale note nobody tagged or linked still competes as current.
- **Roles are conventions.** Any process that can run the CLI can run curator commands or `status consolidated`. Git history makes misuse visible, not impossible.
- **Secret detection is pattern-based.** Patterns catch common formats. A bare password with no keyword, or a credential in a format the engine does not know, passes. The rule "store where a secret lives, never its value" still depends on the writer.
- **Weights need traffic.** With little use, weights are dominated by in-degree (0.5 per incoming synapse), and the Hot list stays empty until reads accumulate.
- **Single-machine design.** Siblings are found by relative path, and locks are local files. Several machines sharing a vault would need git merges of `usage.jsonl`, which is deliberately not tracked.
- **English storage.** Queries may arrive in Spanish, but storage is English, and only a Spanish→English path exists.

## 12. Future work

A versioned stemmer fix, with the benchmark rerun. A visible marker for `truth: superseded` in recall output. An optional embedding re-ranker behind the same budgets. Role enforcement through per-agent keys on write commands. A merge driver for usage logs, so vaults can be shared across machines. Glossaries for other languages. A public benchmark built from the demo vault, so that thresholds such as `GATE_COVERAGE`, `FAMILY_LIFT` and `HEBB_THRESHOLD` can be tuned in the open.

```bash
$B recall "when should the beds be watered"
S=$($B session new --mode quick | head -1); $B recall "slug pest" --session $S --no-body
$B read "Slugs are the main pest" --session $S; $B read "Pests" --session $S; echo "exit $?"

for i in 1 2 3; do S=$($B session new | head -1)
  $B credit --used "Copper tape kept slugs off bed B" "The drip timer runs 20 minutes at 7 am" --session $S; done

```
